# CELL DEFENDER — 工程執行總規範 V1.0

- 日期：2026-11-04
- 正式倉庫：https://github.com/SunTung/CELL-DEFENDER
- 平台：Android 優先，iOS 架構相容；Unity 2022 LTS 系列（精確版本需實際建置驗證）
- 產品：9:16 直式、16-bit 像素、生物機械、人體內部防衛射擊遊戲
- 開發模式：GitHub 為唯一正式程式來源，GitHub Actions 雲端建置，手機下載 APK 驗收
- 本文性質：工程執行規格，不代表所列項目已實作或通過測試

## 0. 不可變更的產品基準

### 遊戲循環
六關固定流程 → 通關後無盡模式。每關有敵群、資源、升級、小頭目、關底頭目。玩家由人類細胞構成的智能防衛者，六階外觀進化；角色經驗等級、進化階段、技能等級三者獨立儲存。

### 四類技能，每類六級
- 子彈：Lv1 單發；Lv2 雙發平行；Lv3 子彈速度+10%；Lv4 三向散射 -7°/0°/+7°；Lv5 穿透1個敵人；Lv6 五向 -14°/-7°/0°/+7°/+14°。
- 射線：Lv1 基礎；Lv2 長度+30%；Lv3 傷害+20%；Lv4 雙線；Lv5 貫通；Lv6 三線。
- 防禦：Lv1 15%生命值護膜；Lv2 25%；Lv3 每5秒回復1%生命；Lv4 減傷10%；Lv5 未受傷8秒後每秒恢復2%最大生命值的護膜；Lv6 每30秒一次免傷及1秒無敵。
- 分身：Lv1 1個30%基礎攻擊；Lv2 2個；Lv3 每個40%；Lv4 每個雙發、每發60%分身單發傷害；Lv5 自動追蹤；Lv6 3個。
- 每次經驗升級顯示最多3個合格技能；不得重複取得相同技能等級；前級為下一級前提。若技能池已滿，改給明確定義的資源獎勵，不可死鎖。
- 創傷：生命歸零降低經驗等級，最後取得技能暫時失效；恢復順序、最低保護等級及存檔規則需測試確定。

### 七類敵人
1. 左右移動型 2. 防禦型 3. 激進型 4. 逃離型 5. 固定位置型 6. 母體型 7. 頭目型。
行為與武器獨立組合，母體召喚是能力而非第七種攻擊。

### 六種攻擊
追蹤子彈、撞擊、直射子彈、擴散子彈、長段固定方向飛行光束、中段固定方向飛行光束。兩種光束都是沿發射方向移動的長條投射物，不是持續轉向雷射。

### 三種道具
補血：最大生命25%；護罩：抵擋3次傷害，暫定總上限9次；能量：累積至升級門檻。護罩次數優先於技能護膜消耗；拾取、上限及受擊無敵幀須有測試。

### 六關
1 血液防線；2 肺泡感染；3 腸道危機；4 肝臟毒域；5 神經網路；6 核心異變。無盡模式逐步提升敵群與難度，避免無限制產生物件導致手機崩潰。

## 1. 架構原則

- Unity C#；ScriptableObject 保存敵人、武器、技能、波次、道具數據；Prefab 保存可重用實體；Scene 管理場景；不要把全部遊戲放在單一 MonoBehaviour。
- 系統分離：Core/GameState、Input、Player、Movement、Combat/Projectile、Enemy/AI、Spawner/Waves、Skills、Progression、Pickups、Stage/Boss、UI、Audio、Save、Editor/Build。
- 移動、碰撞、受傷、死亡、掉落與升級有明確事件；傷害結算只經一個入口，避免多重扣血。
- 手機單指拖曳、玩家自動射擊；升級時暫停；9:16 安全區適配；最低效能目標先以60 FPS、降級30 FPS策略測試，不假稱已達成。
- 投射物、敵人、特效、掉落物使用物件池；設上限與回收策略；避免每幀 GC 配置。
- iOS 保持輸入與平台抽象，但 GitHub Linux runner 無法直接完成 iOS 正式簽署與 IPA，另需 macOS/Xcode 環境。

## 2. 美術一致性規範

- 16-bit 風格：固定像素密度、統一角色輪廓、色盤、邊緣高光、動畫節奏；不要混用寫實圖、平滑3D與低解析度角色。
- 角色：青綠/象牙白；敵人：紫紅/病變橘；補血：綠；能量：金；護罩：青藍；背景：暗紅與深藍；UI：深色半透明生物機械邊框。
- 建議素材尺寸：小物16×16或32×32；普通敵人32×32/64×64；頭目128×128以上；所有素材的Pixels Per Unit、Filter Mode=Point及切圖規則統一。
- 六關場景不同，但HUD、角色、彈幕語意色、受擊閃爍、道具圖標和字體不變。
- 美術資產每件記錄：asset_id、用途、尺寸、動畫幀數、碰撞區域、來源、版本、匯入狀態、驗收狀態。
- 圖像概念稿≠已匯入遊戲的可用精靈素材；須切圖、去背、整理透明度、設置匯入參數並驗收。

## 3. 分期實施與完成定義

### P0 — 建置基礎（最高優先）
工作：核實Unity Editor精確版本及GameCI相容性；修正manifest/ProjectSettings；建立可序列化主場景、Build Settings、Android輸出設定；修正Actions授權、APK路徑及Artifact。
驗收：Actions實際執行成功，日誌包含Unity版本、構建結果、APK存在且大小>0；記錄commit SHA與run URL。未有成功run不得標記PASS。
注意：目前僅有原型檔案，沒有已驗證APK；授權Secrets需使用者自行配置，不得寫入倉庫。

### P1 — 手機可玩垂直切片
工作：角色移動、自動射擊、至少三種敵人、直射/撞擊、生命/能量/升級、補血、護罩、暫停、重新開始、觸控安全區。
驗收：APK安裝啟動、觸控跟手、射擊命中、敵人死亡與道具生效、無致命例外；錄製手機測試或保存手動測試清單。

### P2 — 完整戰鬥行為
工作：七類AI、六類攻擊、母體增殖、頭目階段、投射物池、攻擊預警、撞擊/無敵幀。
驗收：每類AI可獨立測試，六種攻擊方向、碰撞、回收正確；母體有生成上限；頭目轉階段可重現。

### P3 — 進化、技能、創傷與存檔
工作：四類各六級、合格技能抽選、六階形態、經驗曲線、掉級、護罩/技能護膜優先級、存檔版本。
驗收：24個技能等級可逐項驗證；重複抽選為零；技能升級及創傷後狀態一致；重啟可恢復存檔。

### P4 — 六關完整內容
工作：六關波次資料、每關小頭目與關底頭目、場景變化、獎勵及通關條件。
驗收：可由第一關連續通關第六關；每關至少一個專屬環境機制與頭目攻擊組合；流程不死鎖。

### P5 — 無盡模式
工作：六關通關解鎖、難度增長、敵群生成預算、紀錄分數、死亡結算。
驗收：解鎖條件正確、可持續生成且受效能上限約束、可退出重開。

### P6 — 美術與音效統一
工作：角色六階、七類敵人、頭目、彈幕、三道具、六關背景、UI、逐格動畫、音效與BGM。
驗收：素材清單逐項通過；像素密度、色盤、尺寸、錨點與碰撞一致；無缺圖/缺音/錯誤引用。

### P7 — Android封裝與發行
工作：正式應用ID、圖標、版本號、ARM64、Keystore簽署、Release建立、APK下載與安裝說明。
驗收：正式簽署APK可安裝、升級不丟存檔、Release與Commit對應、SHA-256及建置日誌留存。正式簽署金鑰絕不提交Git。

### P8 — 效能、回歸與交付
工作：低中階Android裝置測試、FPS/記憶體/發熱、密集彈幕、觸控、存檔、6關全流程與無盡模式。
驗收：記錄裝置型號、Android版本、FPS分布、峰值記憶體、崩潰及修復；所有阻斷問題關閉後才標記正式完成。

## 4. 每次執行的固定程序

1. **定位**：讀取本報告、STATUS.md、最近成功run、最近commit；只檢查已驗證產物是否仍存在，不重新執行完整測試。
2. **選任務**：按P0→P8的依賴順序，選出可執行且尚未完成的工作；明確列出輸入、預期輸出及驗收條件。
3. **實作**：在既有檔案與架構上增量修改；避免無理由改名、刪除、重建；大型修改用獨立分支與PR。
4. **靜態檢查**：確認檔案、引用、設定與資料一致；不能將靜態檢查稱為Unity編譯成功。
5. **執行驗證**：能運行Actions就取得run結果；需手機或Unity授權時標為BLOCKED_EXTERNAL並繼續其他獨立任務。
6. **修復**：只針對有證據的錯誤修復；每次記錄原因、修改檔案、回歸範圍與結果。
7. **封存**：成功產物記錄SHA、commit、run、artifact、測試條件；驗證後不因換對話而重做。
8. **報告**：更新STATUS.md：DONE_VERIFIED、DONE_UNVERIFIED、IN_PROGRESS、BLOCKED_EXTERNAL、TODO；列出下一個工作。

## 5. CI/CD 與授權

- Actions：workflow_dispatch手動啟動，必要時對PR執行靜態檢查；正式建置僅在設定可用時執行。
- Unity Editor版本必須和ProjectVersion匹配；先確認該版本存在且GameCI支援，不能依賴虛構revision。
- Unity授權/啟用因Unity版本與授權方案而異，先按GameCI官方相容文件配置；不要假定UNITY_LICENSE等Secrets必然足夠。
- Debug APK可先驗證安裝；正式Release使用Android Keystore及密碼Secrets；不得把私鑰與密碼寫入repo。
- 建置輸出採Artifacts，驗證成功後再發Releases；檢查APK存在、非零大小、簽署與版本資訊。
- Actions失敗時分類：授權、Editor版本、Packages、編譯、場景、Android SDK/NDK、簽署、Artifact；逐項修復。

## 6. 測試矩陣

- T01 啟動與直式解析度；T02 單指拖曳；T03 自動射擊；T04 七類敵人移動；T05 六種攻擊；T06 命中/碰撞/死亡；T07 三道具；T08 四類24級技能；T09 六階進化；T10 創傷掉級；T11 六關流程；T12 頭目階段；T13 無盡模式；T14 存檔恢復；T15 密集彈幕效能；T16 APK安裝升級。
- 每個測試存：test_id、版本、輸入、期望、實際、PASS/FAIL/BLOCKED、證據連結。
- 僅重測本次改動影響的測試與必要回歸；對已封存的未改動測試保留有效結果，除非依賴或環境已改變。

## 7. 版本與進度管理

- 本報告為固定執行規範；STATUS.md為即時進度；CHANGELOG.md記錄實際變更；驗收證據可放docs/evidence/。
- 版本：v0.1建置原型、v0.2戰鬥核心、v0.3技能與存檔、v0.4六關、v0.5無盡、v0.9內容完整測試、v1.0正式版。版本號是目標，不等於完成。
- 只保留最新有效的交付主線；歷史commit可追溯，不刪除唯一可運作版本。
- 換對話時先讀STATUS.md與本報告，從最後一個已驗證checkpoint續作。

## 8. 外部阻礙與處理原則

- Unity授權需使用者登入/配置Secrets：BLOCKED_EXTERNAL；其餘程式與資料設計繼續。
- Android實機安裝需使用者在手機確認：BLOCKED_EXTERNAL；雲端靜態/編譯驗證繼續。
- 美術尚未完成：可用標準化臨時圖形先完成機制，但不可標記正式美術PASS。
- 若GitHub Actions權限/配額/執行不可用：記錄精確錯誤，不捏造run；繼續可獨立實作的模組。
